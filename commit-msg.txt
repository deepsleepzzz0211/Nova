feat(cli): non-interactive print mode + real-LLM E2E suite

nova -p "prompt" runs one turn without the TUI: the answer streams to
stdout, tool calls go through the normal pipeline (denied unless --yes,
since no dialog is possible), and the process exits non-zero when the
provider reports an error. --model accepts provider/model, so invocations
are self-contained (no config edits).

E2E suite (tests/e2e, pnpm test:e2e, vitest.e2e.config.ts) drives the
BUILT binary as a subprocess against a real endpoint with a temp NOVA_HOME
that seeds its own catalog: plain answer + exit code, tool call creating a
file, session JSONL persistence, unknown-provider failure. Assertions are
structural invariants only (never model wording); a missing key skips with
a message and a rate-limited provider retries once then skips, so free
tiers cannot produce false failures.

Two real bugs found while wiring a second provider:
- resolveSpec (/model and subagent routing) always passed the config-level
  base_url/api_key, so switching to a different catalog provider sent the
  request to the wrong endpoint with the wrong key
- the CLI --model flag could not route to a provider at all; provider/model
  specs now switch provider and drop the previous provider''s overrides
- config schema: apiKey/baseUrl are optional (unset = catalog default)

Verified: 4/4 E2E tests green against chatapi.weixin.qq.com
(weixin/Deepseek-v4-flash) in ~16s; 662 unit/component tests green.
