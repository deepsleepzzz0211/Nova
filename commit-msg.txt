feat(tui): static/dynamic render partition (ticket tui-refactor 08)

Long conversations no longer re-render their whole history every 32ms
stream commit:

- message-partition module (pure, 5 tests): idle conversations are fully
  static; while streaming the in-flight message is held out of the static
  region (its deltas update in place), and it joins the static region when
  the stream ends — partitioning keeps completed message identity stable
  across deltas
- ChatView renders completed messages through Ink's <Static>, so they are
  written once and leave React reconciliation; the live message, todo view
  and input/status regions are the only dynamic area
- MessageBubble and ToolCallView are React.memo components; App's
  displayKind resolver is useCallback-stable so memoisation is not
  invalidated every render
- 10 new tests: partition unit tests, ChatView static/live behaviour
  (exactly-once per rendered frame, finish transition, empty state) and a
  memo-type assertion

Note: max-render-cost verification on a real terminal remains part of the
manual TUI acceptance pass.
