spike(e2e): adopt @microsoft/tui-test for TUI interaction tests (GO)

Decision: use the tui-test JS binding inside vitest (single runner) with the
xtermjs backend. Evidence recorded in the spike suite and summarised here.

Verified on Windows against a real endpoint (weixin/Deepseek-v4-flash):
- PTY launch of the built binary and an Ink render assertion
- resize (100x32 -> 70x24) with the editor still visible
- real LLM round trip rendered inside the PTY (submit -> PONG visible)
- keyboard events accepted (Ctrl+O), SVG screenshot written, .cast
  recording produced
- both backends work without external terminals (xtermjs is CI-friendly,
  alacritty is also bundled)

Limitations found and worked around:
- tui-test cannot track the exit code of a program started via run(), so
  exit-code assertions stay in the print-mode E2E suite
- screenshot() does not create the target directory
- nova needs an explicit --model provider/model in isolation (otherwise the
  default provider is used and the SDK reports missing credentials)

Next: ticket 03 promotes this harness into tests/e2e/tui with the real
interaction cases (Ctrl+O expand, Esc interrupt, /undo, permission dialog,
narrow-terminal wrapping).

devDependency: @microsoft/tui-test@0.1.0-beta.3 (pinned). 662 unit tests
remain green; the spike suite is opt-in via pnpm test:spike.
